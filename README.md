# RatingSystem 智能考试辅助评分系统

RatingSystem 是面向教师的本地辅助阅卷系统。学校现有的极域课堂负责考试和收卷，本项目负责读取教师准备的评分方案和学生 DOCX 答卷，生成建议分数，供教师审核后形成最终成绩。

系统不是在线考试平台，不包含学生登录、在线交卷、防作弊或完整用户管理功能。

## 业务流程

1. 教师手动创建评分方案，或上传文字型 DOCX 试卷，由 AI 生成可编辑草稿。
2. 教师核对并确认评分标准。修改任何评分标准后，系统会自动撤销确认，必须重新确认才能批量评分。
3. 教师上传全班 DOCX 答卷 ZIP，查看每名学生的身份、解析结果和异常。
4. 正常答卷无需逐份确认；教师只修正异常学生的身份、题目映射或答案文本。
5. 教师点击一次“确认并开始评分”，系统自动确认正常答卷、正式导入并启动批量建议评分。重复点击不会产生重复答卷或重复评分任务。
6. 单份答卷失败不会中断其他答卷；页面会显示失败阶段，修正后可以安全重试。
7. 教师逐题查看原始答案、标准答案、建议分、评分理由和评分点，接受建议分或填写实际分数。
8. 只有整份答卷的所有题目都已由教师确认实际分数，系统才生成正式总分。

`suggestedScore` 是程序或 AI 提供的建议分，`actualScore` 是教师确认的实际分。正式成绩只汇总 `actualScore`，不会把建议分自动当作最终成绩。

## 环境要求

- Java 17
- Maven 3.9 或项目自带的 Maven Wrapper
- MySQL 8
- 支持现代 JavaScript 的浏览器
- 如需 AI 建议评分，需要可用的 DeepSeek API Key 和网络连接

项目使用 Flyway 管理数据库结构。首次连接空数据库时会依次执行 V1、V2、V3 迁移；不要修改已经在目标数据库执行过的迁移文件。

## 配置

数据库密码始终通过环境变量提供。DeepSeek 配置既可以继续使用环境变量，也可以在教师网页的“系统设置”中保存。不要把任何真实密码或 API Key 写入源代码、HTTP 测试文件或 Git 仓库。

PowerShell 示例：

```powershell
$env:DB_URL = "jdbc:mysql://localhost:3306/rating_system?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai"
$env:DB_USERNAME = "请填写数据库用户名"
$env:DB_PASSWORD = "请填写数据库密码"

$env:AI_API_KEY = "请填写教师或学校自己的 DeepSeek API Key"
$env:AI_BASE_URL = "https://api.deepseek.com"
$env:AI_MODEL = "deepseek-flash"
```

网页保存的 AI 配置优先于 `AI_API_KEY`、`AI_BASE_URL` 和 `AI_MODEL` 环境变量，并且保存后立即供新发起的 AI 评分使用，无需重启程序；已有评分结果不会改变。网页中的 API Key 输入框始终留空，留空保存表示保留原密钥，后端也不会把完整密钥返回浏览器。

本机 AI 配置默认保存在 Git 仓库之外：Windows 为 `%LOCALAPPDATA%\RatingSystem`，其他系统为当前用户目录下的 `.ratingsystem`。API Key 使用 AES-GCM 加密保存，配置文件和本机密钥文件限制为当前操作系统用户访问。需要改变位置时可以设置 `RATING_SETTINGS_DIR`。这项保护适用于单用户本机部署；仍应保护操作系统账户，不要共享该目录。

教师可以在“系统设置”中主动点击“测试连接”。测试会向模型发送一次最小请求，可能产生少量 API 费用，系统不会在启动或保存时自动测试连接。

正式交付时必须由教师或学校配置自己的 DeepSeek API Key，不能依赖开发者个人密钥或个人额度。不要把真实密钥复制到 README、`application.properties` 或 Git 仓库。

## 启动与打包

在项目根目录执行：

```powershell
$env:JAVA_HOME = "Java 17 的安装目录"
.\mvnw.cmd spring-boot:run
```

启动成功后使用浏览器访问：

```text
http://localhost:8080
```

应用默认只监听 `127.0.0.1`，同一台电脑之外无法访问。当前版本没有身份认证，请保持该默认设置，不要直接开放到公网。

运行测试和生成可执行包：

```powershell
.\mvnw.cmd test
.\mvnw.cmd package
```

生成的 JAR 位于 `target` 目录，可使用 Java 17 启动：

```powershell
java -jar target/rating-system-0.0.1-SNAPSHOT.jar
```

## 教师使用步骤

### 1. 准备评分方案

首页只提供“创建新试卷”和“打开试卷库”两个入口。所有历史试卷统一放在独立的试卷库中，可以按名称搜索、打开或在符合数据保护条件时删除。右上角齿轮进入独立的“系统设置”，其中只提供 AI 配置。新试卷可以手动录入，也可以上传文字型 DOCX 试卷及可选的答案 DOCX，由 AI 生成草稿。AI 导入不会直接创建正式试卷：题目原文优先保留，AI 推导的答案和不确定边界会标为待核对，教师必须检查、修改并保存。

进入试卷工作区后，核对每道题的题型、题干、满分、标准答案、评分细则和结构化评分点。确认无误后点击“确认评分标准”。

如果之后再次修改标准答案、分值、评分细则或评分点，确认状态会被撤销，重新确认前不能启动批量评分。

### 2. 上传和核对答卷

将全班答卷打包为 ZIP。每名学生一个文件夹，文件夹名与 DOCX 文件名均采用 `学号_姓名`，例如：

```text
990000001_测试甲/990000001_测试甲.docx
990000002_测试乙/990000002_测试乙.docx
```

上传 ZIP 后先查看班级汇总。正常答卷默认折叠，仍可按需展开检查；身份不一致、缺题、题目映射歧义或答案边界异常的答卷会单独列出，必须先修正。全部异常处理完成且评分标准已确认后，点击“确认并开始评分”完成正式导入并启动评分。

### 3. 建议评分和人工审核

选择题、判断题和精确匹配填空题由程序比对；AI 模式填空题和简答题可以调用 DeepSeek 生成建议分与理由。首次使用或更换学校的 API Key 时，点击页面右上角齿轮进入“系统设置”，保存 API Key、Base URL 和模型名称；有需要再主动测试连接。

AI 调用失败时不能自动记为零分。教师可以在自动评分失败后手动填写实际分数。所有最终分数都必须由教师确认。

### 4. 编程题限制

系统仅保存和展示编程题的文字或代码答案，不会编译、执行或验证学生代码，也不会声称程序已经运行成功。编程题必须由教师根据题目要求人工评分并确认实际分数。

### 5. 查看成绩

全班成绩页面展示学生姓名、学号、逐题审核状态、实际分数和最终总分。未完成全部题目审核时，当前已确认分数仅表示审核进度，不是正式总分。

## 安全与使用限制

- 当前版本没有身份认证和权限控制，默认仅监听 `127.0.0.1`，只适合受控的本机环境，不得直接暴露到公网。
- 成绩修改接口在正式服务器部署前必须增加访问控制，或接入学校现有认证与服务器访问限制。
- AI 只提供建议，可能出现错误或不稳定结果，教师必须人工审核。
- 编程题不会实际运行代码。
- 试卷 AI 导入和学生答卷解析当前仅支持文字型 DOCX；不支持 TXT、PDF、OCR、扫描图片或直接选择文件夹上传。
- 当前不提供学生端、在线考试、防作弊、全班排名、成绩导出、成绩发布或复杂统计功能。
- 学生答卷、测试 ZIP、数据库备份、日志、HTTP 响应文件和任何密钥都不应提交到 Git。
